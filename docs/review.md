# Самоперевірка функціонального MVP

Дата: 23.11.2026. Перевірено на локальній PostgreSQL 16.16 через справжні HTTP-запити та браузер. Це самоперевірка реалізації, а не незалежне рев’ю або формальний звіт Лаб №6.

## Функціональні сценарії

| Сценарій | Перевірений результат |
|---|---|
| Чиста міграція й початкові дані | Схеми та обмеження створено; 240 запитань, 3 курси |
| Реєстрація і вхід | Профіль створюється; пароль перевіряється; повторний email відхиляється |
| Контроль доступу | Без JWT кабінет недоступний; учень не читає банк адміністратора чи чужий результат |
| Банк завдань | Адміністратор створює чернетку та нову версію; попередній текст зберігається, некоректний ключ відповіді відхиляється |
| Діагностика | Проходиться 15–20 завдань; MathScore зберігається в акаунті; повтор до 30 днів відхиляється |
| Повтор відповіді | Той самий ключ і дані не додають другу відповідь; змінені дані дають конфлікт |
| Резерв і тестова оплата | Створюється реальний Enrollment; повторний запис на курс заборонено; підтвердження ідемпотентне |
| Одночасний підбір | 6 учнів однакової когорти/бала/слота розподілено у 2 групи; понад 5 місць не зайнято |
| Старт групи | Після 3 підтверджень стан Open, чинні резерви не підвищують ActiveCount |
| Учень до 16 років | До коду вхід заборонено; код з власної тестової пошти активує акаунт; оплату підтверджують батьки |
| Сесії | Refresh ротується; вихід відкликає новий і попередній JWT цієї сесії |
| Користувацький інтерфейс | Через браузер створено акаунт, пройдено діагностику, зарезервовано й підтверджено запис |
| Відновлення сторінки | Після перезавантаження тест продовжився з 6-го завдання, попередні відповіді збережено |
| Адаптивність | Кабінет перевірено на desktop і ширині 390 px; горизонтального переповнення не виявлено |

Повний цикл `Stop-MathHub.cmd` / `Start-MathHub.cmd` перевірено через ті самі PowerShell-скрипти у Windows PowerShell 5.1 з основної папки проєкту. Повторний запуск розпізнає власний активний процес і не створює дубліката. Після перезапуску PostgreSQL та API збережено акаунт, відповіді, MathScore та Active-запис. Зібраний React і API працюють за однією адресою `http://127.0.0.1:5080`.

Додатково перевірено: прострочений резерв не займає місце, повторне резервування на курс стає доступним, новий резерв можна скасувати; сторонній Origin відхиляється; повторне використання старого refresh-токена відкликає всю сесію. Backend Release та frontend зібрано без помилок, Prettier перевірку пройдено. Перевірка відомих вразливостей NuGet (з транзитивними залежностями) та production npm-залежностей не знайшла вразливостей на дату перевірки.

## Рішення після перевірки

- Обмеження частоти запитів застосоване до реєстрації/входу/refresh, а не до звичайного оновлення кабінету.
- Некоректний JSON повертає помилку клієнта; подробиці БД не повертаються у відповіді.
- Перехід від результату до каталогу не змінює сторінку кабінету.
- Батьківська тестова пошта визначається конфігурацією API, тому доступна і при запуску зібраного UI у Development.
- Секрети та дані `.local/`, node_modules, bin/obj не включаються до Git.

Навантажувальні цілі, відсоток покриття, повна відповідність усім FR/NFR та готовність до production у цьому документі не заявляються. Початкові завдання не є педагогічно відкаліброваним банком; платіжний шлюз і доставка пошти локальні тестові.
