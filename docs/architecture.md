# Архітектура й межі етапів

Модульний моноліт ASP.NET Core 8; цільове сховище наступного етапу — PostgreSQL 16 / EF Core 8; клієнт React 18 + TypeScript.

## Лаб №4
Основні класи, контракти, залежності, робочий HTTP host і початковий інтерфейс. Доменні обмеження з Лаб №1–2 зберігаються. Клієнтський приклад не є офіційною діагностичною сесією.

## Лаб №5
Завершення MVP: Identity/JWT, керування банком завдань, збереження тестів, PostgreSQL-репозиторії та міграції, інтеграція UI, захищений запис. Операції з групою — під SELECT FOR UPDATE з повторним читанням складу. Перевірка дубль-запису потрібна за курсом, не лише за групою. Платіж виконується поза блокуванням, підтвердження — в одній локальній транзакції. Межі MVP щодо резервів/оплати й батьківської згоди мають бути явно погоджені до завершення інтеграції.

## Лаб №6
Unit, component, system, concurrency та load checks; покриття й матриця вимог. У Лаб №4 немає тверджень про 70% покриття, 200 активних сесій чи підтвердження продуктивності.

## Рішення
Лічильники групи похідні. Резерви займають місця, але не змінюють ActiveCount; прострочення резерву не переводить ClosedFull в Open. Вік і слоти фільтруються application-сценарієм; статуси й Δ перевіряються доменом. Алгоритм використовує snapshot бала на момент запису.
