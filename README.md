# MathHub

Освітня платформа для діагностики знань і формування математичних мінігруп. Автор: Друченко Олексій Сергійович, ІК-41.

## Що працює

Це функціональний локальний MVP: React → ASP.NET Core 8 → PostgreSQL 16. Дані не зникають після оновлення сторінки або перезапуску сервера.

- Реєстрація учня та батьків, вхід, вихід, захищений кабінет. BCrypt, JWT на 60 хвилин і ротація refresh-токенів із відкликанням сесії.
- Для учня до 16 років: підтвердження зв’язку з батьками кодом на 24 години. Для локальної демонстрації лист зберігається у тестовій пошті; зовнішні листи не надсилаються.
- Діагностика з 6 контекстами та початковим банком із 240 завдань. Перевірка відповідей на сервері, адаптивний Elo, 15–20 завдань, MathScore 0–100, 6 рангів / 18 підрангів. Продовження незавершеної сесії після перезавантаження; повторна діагностика через 30 днів.
- Каталог із 3 курсами та вибором розкладу. Підбір групи за курсом, віковою когортою, розкладом і розкидом MathScore ≤ 5.
- Резерв на 15 хвилин, скасування резерву, тестове підтвердження оплати. До 16 років оплату підтверджують батьки. Резерви займають місця, але не збільшують кількість підтверджених учнів. Група готова від 3 підтверджень, максимум — 5 зайнятих місць.
- Кабінет адміністратора: перегляд, створення й нові версії завдань. Ключі відповідей доступні лише адміністратору.
- EF Core міграція, зовнішні ключі, унікальні індекси, транзакції та блокування PostgreSQL для запису в групи.

## Сторінки та швидка перевірка

У головному меню доступні **Курси**, **Наші викладачі**, **Групи та записи**, **Оплата** та **Мій кабінет**.

- `#/courses` — три демонстраційні курси з БД, ціни, розклад, переходи до груп і перевірки оплати.
- `#/teachers` — Друченко Олексій Сергійович та Гриценко Марина Миколаївна; фотографії й надані відомості про навчання.
- `#/groups` — після входу учня: свої групи/записи, вибір курсу і слота, резерв на 15 хвилин, оплата або скасування. До MathScore спочатку пройдіть діагностику у кабінеті. Група підбирається автоматично, відкритого списку чужих учнів немає.
- `#/payments` — тестова оплата чинного резерву, історія квитанцій та окрема демонстрація оплати без запису в групу. Для швидкої перевірки достатньо акаунта від 16 років або батьківського акаунта: оберіть курс, сценарій «Успішна» / «Відхилена», виконайте оплату та оновіть сторінку. Квитанції зберігаються в БД. Номер картки не потрібен.

**Демооплата без групи не є підтвердженим записом на курс.** Для справжнього в межах MVP Enrollment потрібен ланцюжок діагностика → резерв → тестове підтвердження. До 16 років оплату виконує хтось із батьків.

Докладна звірка того, що є у звіті та де це перевірити: [docs/report-audit.md](docs/report-audit.md).

## Запуск у Windows

Потрібні **.NET SDK 8.0.4xx або новіший SDK 8** та **Node.js 22+** у PATH. Перший запуск потребує інтернету для залежностей і portable PostgreSQL 16.16 з офіційного джерела EDB. Інсталятор і права адміністратора не потрібні; наявні служби PostgreSQL не змінюються.

1. Відкрийте папку проєкту та запустіть `Start-MathHub.cmd`.
2. Дочекайтеся збірки. Скрипт відкриє **http://127.0.0.1:5080**. Фронтенд і API працюють за однією адресою.
3. Натисніть «Мій кабінет» → «Реєстрація». Для швидкої демонстрації дорослого учня вкажіть дату народження, що відповідає віку від 16 років.
4. Пройдіть діагностику, оберіть курс і розклад, зарезервуйте місце та підтвердьте його тестовою оплатою.
5. Для завершення роботи запустіть `Stop-MathHub.cmd`. Акаунти та результати збережуться.

У VS Code: **File → Open Folder → MathHub**, потім у терміналі:

```powershell
.\scripts\Start-MathHub.ps1
```

Скрипт перевіряє PID і час створення власного процесу; повторний запуск відкриває вже запущений сайт. Після редагування коду спочатку зупиніть і знову запустіть проєкт. Якщо порт 5080 або 55432 зайнятий іншим застосунком, звільніть його: скрипти не завершують сторонні процеси.

## Як користуватися сайтом

### Ролі та доступ

| Роль | Доступні дії |
|---|---|
| Гість | Перегляд головної сторінки, демонстраційне завдання, реєстрація та вхід |
| Учень / учениця | Діагностика, власний MathScore, каталог, резервування й перегляд своїх записів; самостійна тестова оплата від 16 років |
| Батьки / опікун | Підтвердження пов’язаного акаунта дитини, перегляд її MathScore та записів, підтвердження тестової оплати |
| Адміністратор | Перегляд, додавання та створення нових версій завдань діагностичного банку |

Роль обирається під час реєстрації між учнем і батьками. Адміністратора через публічну форму створити не можна: локальний акаунт створюється автоматично під час Development-запуску. Кабінети відрізняються за роллю: у батьків немає кнопки проходження діагностики для себе, а в учня немає редактора банку.

### Головна сторінка: що натискати

| Елемент | Що відбувається |
|---|---|
| Логотип MathHub | Перехід на головну |
| «Курси», «Наші викладачі», «Групи та записи», «Оплата» | Відкриття окремих сторінок; «Як це працює», «MathScore», «Питання» прокручують до пояснень |
| «Меню» на вузькому екрані | Відкриття / закриття навігації |
| «Мій кабінет», «Визначити свій рівень» | Перехід до кабінету; без активної сесії відкривається форма входу |
| «Обрати напрям» | Відкриття каталогу курсів; підбір і резерв доступні в розділі «Групи та записи» |
| Варіанти 8, 10, 12, 14 у демозавданні | Сервер повертає приклад розрахунку рейтингу; правильна відповідь — 12 |
| «Спробувати ще раз» | Скидання лише поточного демоприкладу |
| Питання у FAQ | Розгортання / згортання відповіді |

**Демозавдання на головній не є повною діагностикою.** Показаний перехід бала — приклад; він не створює результату в акаунті й не відкриває резервування. Для власного MathScore потрібна реєстрація та повна діагностика у кабінеті. Деякі пояснювальні тексти вітрини описують розвиток платформи; фактичні доступні дії наведено нижче.

### Сценарій учня від 16 років

1. Відкрийте «Мій кабінет» → «Реєстрація». Оберіть «Учень / учениця», введіть ім’я, дату народження, окремий email, пароль і згоду на обробку даних. Після успішної реєстрації активного акаунта сайт виконує вхід.
2. У блоці діагностики оберіть навчальний контекст: початкова математика, дроби й відсотки, алгебра, підготовка до НМТ або поглиблена математика. Натисніть «Почати діагностику».
3. Оберіть один варіант і натисніть «Підтвердити відповідь». Поки варіант не обрано, кнопка неактивна. Кожна відповідь зберігається на сервері; після надсилання перейти назад і змінити її через інтерфейс не можна.
4. Продовжуйте до завершення: мінімум 15, максимум 20 завдань. Кількість визначає алгоритм, тому завершення на 15-му завданні є нормальною поведінкою. Правильні відповіді під час проходження не розкриваються.
5. Побачте MathScore, ранг і кількість правильних відповідей. Бал враховує складність завдань, тому не дорівнює відсотку правильних відповідей. Перезавантаження сторінки відновлює незавершений тест або збережений результат після входу.
6. Натисніть «Обрати курс», оберіть розклад у картці курсу й «Зарезервувати місце». До отримання MathScore кнопка резервування неактивна.
7. У «Мої записи» з’явиться резерв із терміном дії, зафіксованою ціною та станом групи. Натисніть «Тестова оплата», щоб підтвердити місце, або «Скасувати резерв», щоб звільнити його.
8. Для актуалізації списку та прострочених резервів натисніть «Оновити». «Вийти» завершує поточну сесію, але зберігає акаунт і результати.

**Тестова оплата не списує гроші.** Вона справді змінює запис у локальній БД на підтверджений. Вводити номер картки чи інші платіжні реквізити не потрібно. Після підтвердження кнопка скасування тимчасового резерву зникає: скасування оплаченого навчання через UI ще не реалізовано.

### Сценарій дитини до 16 років і батьків

1. Зареєструйте учня з його власним email та датою народження. У додатковому полі вкажіть інший email батьків / опікуна.
2. Сайт повідомить, що потрібне підтвердження батьків. До активації вхід дитини заблокований.
3. Зареєструйте акаунт із роллю «Хтось із батьків / опікун» **саме на email, зазначений у профілі дитини**. Якщо він уже зареєстрований як батьківський, просто увійдіть. Якщо зараз відкритий інший акаунт, спочатку вийдіть.
4. У батьківському кабінеті знайдіть дитину. Для локальної демонстрації натисніть «Тестова пошта»: код підставиться у поле. Звичайна зовнішня поштова скринька листа не отримає.
5. Натисніть «Підтвердити зв’язок і згоду». Саме ця дія активує акаунт дитини; отримання коду саме по собі його не активує.
6. Вийдіть із батьківського акаунта, увійдіть як дитина, пройдіть діагностику та створіть резерв на курс.
7. Знову увійдіть як батьки й натисніть «Оновити». У записах дитини підтвердьте тестову оплату. Учню до 16 років замість кнопки оплати показується пояснення про підтвердження батьками.

Батьківська «Тестова пошта» працює лише у Development-середовищі та дозволяє читати тільки адресовані цьому акаунту листи. Код дійсний 24 години, доступні 5 спроб. Повторне надсилання простроченого коду через інтерфейс поки відсутнє; для повторної демонстрації використайте нові тестові акаунти з іншими email.

### Кабінет адміністратора

1. Після першого запуску знайдіть `Development.AdminEmail` і `Development.AdminPassword` у `.local/appsettings.local.json`. Увійдіть через звичайну форму входу.
2. У «Переглянути контекст» оберіть частину банку. У списку видно тему, складність, версію, активність і правильну відповідь. Ці дані доступні лише адміністратору.
3. Для нового завдання заповніть контекст, тему, текст, чотири різні варіанти, правильну відповідь **точно як один із варіантів** і складність 0–100. Позначка «Активне завдання» визначає, чи можна вибирати його для нових кроків діагностики.
4. Натисніть «Зберегти». Для зміни наявного завдання натисніть «Редагувати», внесіть зміни й збережіть: створиться нова версія, а попередня стане неактивною. Питання вже створених сесій не переписуються.
5. «Скасувати» у формі редагування закриває редагування без збереження. Неактивні записи залишаються видимими у списку.

Зміни адміністратора зберігаються у справжній локальній БД і впливають на діагностику. Для знайомства з редактором можна додати **неактивну чернетку**. Масове вимкнення банку може залишити діагностику без достатньої кількості завдань. Кабінет адміністратора наразі керує питаннями; окремого UI керування користувачами, цінами чи викладачами немає.

## Які перевірки виконує система

Це правила роботи сайту. Вони відрізняються від програмних тестів та майбутнього звіту про тестування у Лаб №6. Частина перевірок є у формах для зручності; сервер повторно перевіряє дані та права доступу.

| Дія / умова | Очікувана поведінка |
|---|---|
| Порожнє ім’я, некоректний email, відсутня згода | Реєстрація не виконується; ім’я обмежене 100 символами, email — 254 |
| Пароль при реєстрації | Мінімум 10 символів; серверний максимум — 72 байти UTF-8, тому для кирилиці допустима кількість символів може бути меншою |
| Дата народження / роль | Сервер приймає вік 5–100 років; роль Parent доступна від 16 років у поточній реалізації |
| Повторна реєстрація на той самий email | Відхиляється; регістр літер і пробіли по краях email нормалізуються |
| Учень до 16 років | Потрібен окремий коректний email батьків; вхід дозволяється після підтвердження |
| Неправильний пароль | Вхід відхиляється; після 5 невдалих спроб відомий акаунт блокується на 15 хвилин |
| Забагато запитів реєстрації / входу / оновлення сесії | Ліміт 30 запитів за хвилину з однієї IP-адреси; потрібно зачекати |
| Чужий кабінет, результат, запис чи лист | Доступ не надається; батьки працюють лише з підтвердженими пов’язаними дітьми, учні — зі своїми даними |
| Відповідь не на поточне питання або застарілий стан тесту | Сервер відхиляє запит; слід оновити дані й продовжити поточну сесію |
| Повтор доставки того самого запиту | Відповідь або операція запису з тим самим ключем не виконується вдруге; інші дані з використаним ключем спричиняють конфлікт |
| Повторна діагностика раніше ніж через 30 днів | Сервер забороняє починати нову діагностику протягом 30 днів після завершення попередньої; кнопки повторного проходження після результату в поточному UI ще немає |
| Резерв без MathScore / на недоступний слот | Відхиляється |
| Другий чинний резерв або активний запис на той самий курс | Заборонено; запис на інший курс дозволено |
| Підбір мінігрупи | Враховуються курс, вікова когорта, слот і різниця балів ≤ 5; якщо відповідної групи немає, створюється нова |
| Місткість групи | Не більше 5 активних учнів і чинних резервів разом; готовність до старту — від 3 підтверджених учнів |
| Резерв старший за 15 хвилин | Не займає місце й не може бути підтверджений як чинний; список можна актуалізувати кнопкою «Оновити» |
| Повторна тестова оплата підтвердженого запису | Не створює другого платежу чи другого місця |
| Немає зв’язку із сервером | Показується помилка; після відновлення зв’язку можна повторити дію або оновити дані |

## Що можна продемонструвати на захисті

Короткий послідовний сценарій: **реєстрація учня від 16 років → діагностика → результат → оновлення сторінки зі збереженим результатом → вибір курсу і слота → резерв → тестове підтвердження → вихід і повторний вхід**. Окремо можна показати скасування резерву на іншому курсі, батьківське підтвердження та неактивну чернетку адміністратора.

Безпечні приклади перевірок: спроба реєстрації з коротким паролем, повторний email, неактивна кнопка запису до діагностики, збереження тесту після оновлення сторінки. Під час звичайної демонстрації немає потреби навмисно вичерпувати всі спроби входу або коду: це тимчасово обмежить подальші дії.

Підтверджений запис показує стан групи, але **не відкриває відеоурок, чат із викладачем чи домашні завдання**. Наявні вітринні описи напрямів та рангів не означають, що всі майбутні навчальні модулі вже інтегровані. Відновлення пароля, редагування профілю, повторне надсилання коду й скасування підтвердженого запису через UI також поки відсутні. Повторну демонстрацію діагностики можна провести на новому тестовому акаунті; видаляти БД для цього не потрібно.


## Розробка з автоматичним оновленням UI

Ініціалізуйте БД один раз (або після її зупинки), потім запустіть API:

```powershell
.\scripts\Initialize-Local.ps1
```

## Локальні дані та адміністратор

Усе локальне розміщується у `.local/`, яку Git ігнорує:

- `data/` — окремий кластер PostgreSQL на `127.0.0.1:55432`;
- `postgresql/` — portable PostgreSQL 16.16;
- `appsettings.local.json` — випадкові паролі БД, JWT-ключ і дані адміністратора (`Development.AdminEmail`, `Development.AdminPassword`);
- `mail/` — локальні листи підтвердження;
- `api.log`, `api.error.log`, `postgres.log` — журнали запуску.

Для входу адміністратора використайте дані з локального конфігураційного файла. Не додавайте його до Git і не публікуйте скриншоти із секретами. Для перевірки батьківського сценарію зареєструйте дитину з email батьків, потім акаунт батьків із цим email. У кабінеті батьків кнопка «Тестова пошта» доступна лише при Development-запуску API; читати можна тільки листи, адресовані цьому акаунту.

Міграції застосовуються автоматично під час запуску API. Не видаляйте `.local/data`, якщо хочете зберегти акаунти. Для перенесення БД зупиніть застосунок і PostgreSQL та використайте `pg_dump`/`pg_restore` або резервну копію кластера тієї самої версії.

## Структура

```text
src/
  MathHub.Api/             HTTP, авторизація, конфігурація, композиція
  MathHub.Infrastructure/  EF Core, міграції, PostgreSQL-репозиторії, JWT, локальна пошта
  MathHub.SharedKernel/    спільні доменні помилки та контракти часу
  Modules/                Identity, Assessment, Groups, Learning, Billing, Gamification, Notifications
  MathHub.Web/            React, TypeScript, освітня вітрина й кабінети
scripts/                  запуск і зупинка локального середовища
docs/                     архітектура, обмеження, результати перевірки
tests/                    місце для формального набору перевірок Лаб №6
```

Domain не залежить від EF Core, ASP.NET чи UI. Application визначає контракти сценаріїв. Infrastructure реалізує збереження та адаптери, API з’єднує компоненти. Для MVP використовується одна БД та один сервер без мікросервісів, брокера повідомлень і додаткових шарів без потреби.

## Межі MVP

Платежі — **явний mock**, реальних списань, банківських реквізитів і платіжних інтеграцій немає. Зовнішню доставку email, відеозаняття, домашні завдання, XP/стріки, реальні розклади викладачів, баланс/автосписання, розширений підбір із згодою на Δ ≤ 10 та розгортання production-середовища ще не інтегровано. Початкові питання й оцінки складності навчальні та потребують педагогічного калібрування. Діагностика не є сертифікацією знань.

Перелік реалізованого не означає виконання всіх 49 FR і 17 NFR зі специфікації. Формальне тестове покриття, навантажувальні вимірювання та звіт Лаб №6 тут не заявляються. Звіт Лаб №4 підготовлено окремо у папці SDLC. Після змін навігації актуальні шляхи перевірки наведено у docs/report-audit.md.
