# MathHub

Освітня платформа для діагностики знань і формування математичних мінігруп. Автор: Друченко Олексій Сергійович, ІК-41.

## Що працює

Це функціональний локальний MVP: React → ASP.NET Core 8 → PostgreSQL 16. Дані не зникають після оновлення сторінки або перезапуску сервера.

- Реєстрація учня та батьків, вхід, вихід, захищений кабінет. BCrypt, JWT на 60 хвилин і ротація refresh-токенів із відкликанням сесії.
- Для учня до 16 років: підтвердження зв’язку з батьками кодом на 24 години. Для локальної демонстрації лист зберігається у тестовій пошті; зовнішні листи не надсилаються.
- Діагностика з 6 контекстами та початковим банком із 240 завдань. Перевірка відповідей на сервері, адаптивний Elo, 15–20 завдань, MathScore 0–100, 6 рангів / 18 підрангів. Продовження незавершеної сесії після перезавантаження; повторна діагностика через 30 днів.
- Каталог із 3 курсами та вибором розкладу. Підбір групи за курсом, віковою когортою, розкладом і розкидом MathScore ≤ 5.
- Резерв на 15 хвилин, скасування резерву, тестове підтвердження оплати. До 16 років оплату підтверджують батьки. Резерви займають місця, але не збільшують кількість підтверджених учнів. Група готова від 3 підтверджень, максимум — 5 зайнятих місць.
- Кабінет адміністратора: перегляд, створення й нові версії завдань. Ключі відповідей доступні лише адміністратору.
- EF Core міграція, зовнішні ключі, унікальні індекси, транзакції та блокування PostgreSQL для запису в групи.

## Запуск у Windows

Потрібні **.NET SDK 8.0.4xx або новіший SDK 8** та **Node.js 22+** у PATH. Перший запуск потребує інтернету для залежностей і portable PostgreSQL 16.16 з офіційного джерела EDB. Інсталятор і права адміністратора не потрібні; наявні служби PostgreSQL не змінюються.

1. Відкрийте папку проєкту та запустіть `Start-MathHub.cmd`.
2. Дочекайтеся збірки. Скрипт відкриє **http://127.0.0.1:5080**. Фронтенд і API працюють за однією адресою.
3. Натисніть «Мій кабінет» → «Реєстрація». Для швидкої демонстрації дорослого учня вкажіть дату народження, що відповідає віку від 16 років.
4. Пройдіть діагностику, оберіть курс і розклад, зарезервуйте місце та підтвердьте його тестовою оплатою.
5. Для завершення роботи запустіть `Stop-MathHub.cmd`. Акаунти та результати збережуться.

У VS Code: **File → Open Folder → MathHub**, потім у терміналі:

```powershell
.\scripts\Start-MathHub.ps1
```

Скрипт перевіряє PID і час створення власного процесу; повторний запуск відкриває вже запущений сайт. Після редагування коду спочатку зупиніть і знову запустіть проєкт. Якщо порт 5080 або 55432 зайнятий іншим застосунком, звільніть його: скрипти не завершують сторонні процеси.

## Розробка з автоматичним оновленням UI

Ініціалізуйте БД один раз (або після її зупинки), потім запустіть API:

```powershell
.\scripts\Initialize-Local.ps1
dotnet run --project src/MathHub.Api
```

В іншому терміналі:

```powershell
cd src/MathHub.Web
npm ci
npm run dev
```

Відкрийте **http://127.0.0.1:5173**. Vite передає `/api` і `/health` на API. Перед переходом між способами запуску зупиняйте попередній сервер.

## Локальні дані та адміністратор

Усе локальне розміщується у `.local/`, яку Git ігнорує:

- `data/` — окремий кластер PostgreSQL на `127.0.0.1:55432`;
- `postgresql/` — portable PostgreSQL 16.16;
- `appsettings.local.json` — випадкові паролі БД, JWT-ключ і дані адміністратора (`Development.AdminEmail`, `Development.AdminPassword`);
- `mail/` — локальні листи підтвердження;
- `api.log`, `api.error.log`, `postgres.log` — журнали запуску.

Для входу адміністратора використайте дані з локального конфігураційного файла. Не додавайте його до Git і не публікуйте скриншоти із секретами. Для перевірки батьківського сценарію зареєструйте дитину з email батьків, потім акаунт батьків із цим email. У кабінеті батьків кнопка «Тестова пошта» доступна лише при Development-запуску API; читати можна тільки листи, адресовані цьому акаунту.

Міграції застосовуються автоматично під час запуску API. Не видаляйте `.local/data`, якщо хочете зберегти акаунти. Для перенесення БД зупиніть застосунок і PostgreSQL та використайте `pg_dump`/`pg_restore` або резервну копію кластера тієї самої версії.

## Структура

```text
src/
  MathHub.Api/             HTTP, авторизація, конфігурація, композиція
  MathHub.Infrastructure/  EF Core, міграції, PostgreSQL-репозиторії, JWT, локальна пошта
  MathHub.SharedKernel/    спільні доменні помилки та контракти часу
  Modules/                Identity, Assessment, Groups, Learning, Billing, Gamification, Notifications
  MathHub.Web/            React, TypeScript, освітня вітрина й кабінети
scripts/                  запуск і зупинка локального середовища
docs/                     архітектура, обмеження, результати перевірки
tests/                    місце для формального набору перевірок Лаб №6
```

Domain не залежить від EF Core, ASP.NET чи UI. Application визначає контракти сценаріїв. Infrastructure реалізує збереження та адаптери, API з’єднує компоненти. Для MVP використовується одна БД та один сервер без мікросервісів, брокера повідомлень і додаткових шарів без потреби.

## Межі MVP

Платежі — **явний mock**, реальних списань, банківських реквізитів і платіжних інтеграцій немає. Зовнішню доставку email, відеозаняття, домашні завдання, XP/стріки, реальні розклади викладачів, баланс/автосписання, розширений підбір із згодою на Δ ≤ 10 та розгортання production-середовища ще не інтегровано. Початкові питання й оцінки складності навчальні та потребують педагогічного калібрування. Діагностика не є сертифікацією знань.

Перелік реалізованого не означає виконання всіх 49 FR і 17 NFR зі специфікації. Формальне тестове покриття, навантажувальні вимірювання та звіт Лаб №6 тут не заявляються. Звіт Лаб №4 буде підготовлено окремо за погодженою структурою попередніх робіт.

## Перевірка збірки

```powershell
dotnet build MathHub.sln --configuration Release
npm --prefix src/MathHub.Web ci
npm --prefix src/MathHub.Web run build
npm --prefix src/MathHub.Web run format:check
```

GitHub Actions виконує збірки backend і frontend. Результати локальної функціональної перевірки описані у `docs/review.md`. Це індивідуальний проєкт: аналіз, реалізацію та самоперевірку виконує автор; незалежне командне рев’ю не заявляється.
